# 注文番号アプリ（スマホ内保存版）

`docs/` がGitHub Pages用のファイルです。ビルド・有料API・外部データベースは不要です。利用者のChatGPT/GitHubログインも不要です。

## 機能

- 担当者追加（名前・数字3桁＋Cのコード）
- 担当者ごとの開始番号と連番発行
- 同じブラウザ内の複数タブはWeb Locksで発行を直列化
- 番号コピー、得意先・メモ・金額、履歴・検索・取消
- バックアップJSON保存・復元
- iPhoneのホーム画面へ追加

## 公開設定

GitHub FreeではリポジトリをPublicにして、Settings → Pages → Deploy from a branch → main /docs → Saveを選びます。独自ドメインは不要です。コードは公開されますが、入力内容は端末のlocalStorageに保存し、GitHubや外部サーバーへ送信しません。GitHub Actionsのワークフローは追加していません。

## 運用

最初に担当者ごとの「次に発行する連番」を設定します。411C000350まで使っていれば351です。未使用の印刷済み用紙を併用する場合は、その最後の番号より後を設定します。発行済み・設定済みの番号より前には戻せません。取消番号は再利用しません。

複数スマホ・別ブラウザ間の共有と重複防止はありません。同じ担当コードは1台の同じブラウザで発行してください。Safariとホーム画面のアプリで保存先が分かれる場合があるため、普段使う開き方を統一してください。プライベートブラウズでは使わないでください。

ブラウザのデータ削除や端末紛失に備えて、定期的にバックアップをファイルへ保存します。復元は履歴の置き換えです。同じ端末で保持している次の番号より前には戻さず、別端末や古いバックアップで不明な使用済み番号は利用者が確認します。新端末での復元後は実際に使った最後の番号を確認してください。

最新版SafariなどWeb Locks対応ブラウザが必要です。保存に失敗した場合は発行番号を表示しません。画面では最新200件を表示し、検索で過去分を絞り込めます。バックアップには全件含みます。

## 検証

番号ロジックの検証：初期設定必須、担当者別連番、100件連続発行、リクエスト再試行、取消後の非再利用、番号を戻す変更の拒否、バックアップ検証、6桁上限。JavaScript構文チェック成功。iPhone実機・ブラウザUIの操作は未検証です。

## 旧共有版のソース

app/・db/等は以前のサーバー共有版のソースです。GitHub Pagesで実行するのはdocs/のみで、共有版APIには接続しません。旧共有版の履歴は自動移行されません。認証情報・実際の注文履歴はこのリポジトリに含みません。
