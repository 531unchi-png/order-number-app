# 注文番号発番アプリ

担当者ごとの「411C＋6桁連番」を共有の保存先で管理するアプリです。

## 機能

- 担当者の追加（名前・数字3桁＋Cの担当コード）
- 次に発行する連番の設定。設定済み・発行済み番号より前へ戻す変更は拒否
- 複数端末による同時発番の重複防止
- 通信失敗時の再試行に対応する発番リクエストID
- 番号コピー、得意先・内容・金額、担当者別履歴と検索
- 取消した番号は欠番として維持
- iPhoneのホーム画面へ追加

## 運用前の確認

設定する数字は「次に発行する連番」です。
411C000350まで使用済みなら351を設定します。
未使用の印刷済み用紙を併用する場合、印刷済みの最後の番号より後から開始してください。
過去の会社側の注文番号は自動照合されません。初期設定は担当者ごとに確認してください。

## ソース管理と稼働先

このリポジトリはアプリのソースコードの管理先です。
現在の試作品は https://order-number-411c.mochi531.chatgpt.site で稼働しています。
GitHubにソースを保存しても、稼働先・発行履歴・共有の保存先は自動で移転されません。
GitHubへの更新を本番に反映する場合は、その変更を稼働先へ反映する必要があります。

GitHub Pagesでは、このアプリのサーバー側APIとD1の処理は実行できません。
このコードをそのままPagesへ公開しても発番機能は動きません。
Pagesに画面を移す場合、共有API・保存先との接続とアクセス制御の設計が必要です。

## 費用

追加の有料APIやサーバー契約は使用していません。
現在のSitesの公開・保存はベータ期間中の対象ChatGPTプラン内です。
利用上限・将来の料金改定は保証されません。
GitHub Actionsや他のホスティングに移す場合は、その無料枠と課金設定を別途確認してください。

## 構成

- React / Vinext
- Cloudflare Workersに対応するサーバー
- D1 / SQLite
- Drizzleによるスキーマ管理と履歴を保ったマイグレーション
- 管理者の識別は、稼働先の認証済みメールと環境設定ADMIN_EMAILを照合
- APIの利用者アクセスは現在の稼働先の共有設定で制御

ADMIN_EMAILの実値・認証情報・実際の発行履歴はこのリポジトリに含めません。
D1の実データはGitHubへ保存しません。

## 開発

Node.js 22.13以降を使用してください。

npm install
npm run dev
npm run db:generate
npm run build

D1のローカル検証では、ビルド後の設定に対してマイグレーションを適用してください。
本番に適用済みのマイグレーションは変更せず、新しいファイルを追加します。
このリポジトリは稼働先のSite IDを埋め込んでいません。
既存の稼働先を更新するときは、そのSiteを正しく選択してください。

## 検証

- TypeScriptの型チェックと本番ビルド成功
- 既存履歴を保持したスキーマ変更
- 担当者2人・100件の同時発番で重複がないこと
- 担当者ごとに独立した開始番号と連番
- 同じ発番リクエストの再試行で追加発番しないこと
- 取消後の番号非再利用
- 番号を前へ戻す設定の拒否
- 6桁連番の上限と上限到達後の既存リクエスト再確認

iPhone実機の画面操作とブラウザのWebMCP連携は未検証です。
